# relationship-cascade-defaults Specification

## Purpose
Define the universal relationship cascade defaults emitted by the standard JDO-to-JPA composition while preserving dependency-derived lifecycle behavior and explicit lower-level configuration.

## Requirements
### Requirement: Standard relationship cascades are limited to persistence propagation
The standard composed JDO-to-JPA relationship migration SHALL supply `CascadeType.PERSIST` and `CascadeType.MERGE` as its universal default cascade members and SHALL NOT universally supply `CascadeType.REFRESH` or `CascadeType.DETACH`.

#### Scenario: Standard many-to-one conversion
- **WHEN** the standard composed migration converts a non-dependent single-valued relationship to `@ManyToOne`
- **THEN** the generated cascade contains `CascadeType.PERSIST` and `CascadeType.MERGE`
- **AND** it does not contain `CascadeType.REFRESH` or `CascadeType.DETACH`

#### Scenario: Standard one-to-many conversion
- **WHEN** the standard composed migration converts a non-dependent collection relationship to `@OneToMany`
- **THEN** the generated cascade contains `CascadeType.PERSIST` and `CascadeType.MERGE`
- **AND** it does not contain `CascadeType.REFRESH` or `CascadeType.DETACH`

#### Scenario: Standard one-to-one conversion
- **WHEN** the standard composed migration converts a non-dependent single-valued relationship to `@OneToOne`
- **THEN** the generated cascade contains `CascadeType.PERSIST` and `CascadeType.MERGE`
- **AND** it does not contain `CascadeType.REFRESH` or `CascadeType.DETACH`

#### Scenario: Standard composition is rerun
- **WHEN** generated source produced with the reduced standard defaults is processed for a second recipe cycle
- **THEN** no cascade member is added, removed, duplicated, or reordered

### Requirement: Dependency-derived lifecycle cascades are preserved
Changing the universal cascade defaults SHALL NOT alter cascade removal or orphan-removal semantics derived from JDO dependency metadata.

#### Scenario: Standard dependent collection conversion
- **WHEN** the standard composed migration converts a collection declared dependent by its JDO metadata
- **THEN** the generated cascade contains `CascadeType.REMOVE`, `CascadeType.PERSIST`, and `CascadeType.MERGE`
- **AND** the generated mapping contains `orphanRemoval = true`
- **AND** the generated cascade does not contain `CascadeType.REFRESH` or `CascadeType.DETACH`

#### Scenario: Standard dependent many-to-one conversion
- **WHEN** the standard composed migration converts a dependent reference to `@ManyToOne`
- **THEN** the generated cascade contains `CascadeType.REMOVE`, `CascadeType.PERSIST`, and `CascadeType.MERGE`
- **AND** it does not contain `CascadeType.REFRESH` or `CascadeType.DETACH`

### Requirement: Explicit cascade configuration remains supported
The lower-level relationship conversion recipes SHALL emit explicitly configured legal cascade members unchanged and SHALL NOT remove `REFRESH` or `DETACH` when a caller deliberately supplies them.

#### Scenario: Explicit refresh configuration
- **WHEN** a caller invokes a lower-level relationship recipe with a `defaultCascade` containing `CascadeType.REFRESH`
- **THEN** the generated relationship cascade contains `CascadeType.REFRESH`

#### Scenario: Explicit detach configuration
- **WHEN** a caller invokes a lower-level relationship recipe with a `defaultCascade` containing `CascadeType.DETACH`
- **THEN** the generated relationship cascade contains `CascadeType.DETACH`

#### Scenario: Explicit custom cascade order
- **WHEN** a caller supplies a supported `defaultCascade` sequence to a lower-level relationship recipe
- **THEN** the generated non-dependency cascade members preserve that configured sequence

### Requirement: Standard default behavior is documented
The project documentation SHALL identify the cascade members generated by the standard composed relationship migration and SHALL explain that refresh and detach propagation require explicit configuration.

#### Scenario: Consumer evaluates migration behavior
- **WHEN** a consumer reads the relationship migration documentation
- **THEN** the documented standard default is `CascadeType.PERSIST` and `CascadeType.MERGE`
- **AND** the documentation identifies `CascadeType.REFRESH` and `CascadeType.DETACH` as explicit opt-in behavior
- **AND** it explains that recipe validation proves generated metadata rather than application-level refresh or detach safety
